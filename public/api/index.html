LubanNav
Route API

为 GitHub Pages 预生成的只读路径 API。无需 JavaScript、无需鉴权，AI 或机器人客户端可直接通过 HTTP GET 获得 JSON。

1. 查询地点 ID

GET ./v1/locations.json

地点绑定不仅包含 roadNodeId，也内嵌对应节点的经纬度和分模式路由节点。

2. 查询内置活动配置

GET ./v1/events.json

返回仓库内置的活动模式、会场角色和地图地点绑定。网页中自定义的活动仅保存在当前浏览器，不会由此静态 API 公开。

3. 下载完整寻路图（后端离线 A*）

GET ./v1/routing-graph.json

文件包含全部节点、边、模式权限与地点绑定。后端缓存这一份 JSON 后，无需另行持有或查询 OSM 数据。

4. 查询预计算路径

GET ./v1/routes/{from}/{to}.{mode}.json

mode 可选 pedestrian 或 robot。路线由 OSM footway/path/pedestrian/service 与分层室内 corridor/elevator 共同构图，并使用 A* 计算。

GET ./v1/routes/main-entrance/library.pedestrian.json
GET ./v1/routes/dorm-5/sports-hall.robot.json
GET ./v1/routes/w2-elevator/third-floor-platform.pedestrian.json

5. 机器人 BLE 协议

GET ./v1/robot-ble-protocol.json

浏览器作为 BLE Central，通过可配置 GATT Characteristic 顺序分包下发路线；小车以通知返回 WGS84 位置、确认和状态。

6. 3D 俯瞰图水泥面候选

GET ./v1/walkable-surfaces.image.geojson
GET ./v1/walkable-surfaces.wgs84.geojson
GET ./v1/walkable-registration-report.json

系统使用 OSM 的 E1–E4、W1–W4 八栋楼与俯瞰图对应中心拟合单应矩阵，同时保留原始归一化图像坐标和 WGS84 版本。两者都包含外部铺装、屋面和潜在立面，全部标记为 routingEnabled=false；完成地面/屋顶复核和垂直连接核验前不会进入寻路图。

响应边界

  • HTTP 200 表示该预生成组合存在；未知 ID 返回 GitHub Pages 的 404。
  • 路线的 segments 是完整有序路段：每段包含起终点经纬度、距离、道路类型、模式权限、来源与 OSM way / 室内要素 ID。
  • path 和 GeoJSON geometry 可直接绘制；无需再用 roadNodeId 查询坐标。
  • 建筑缺少 OSM 入口时，系统使用距离可通行道路节点最近的建筑边界点，并明确标记为推断入口。
  • 室内补丁公开 level、模式权限、数据来源和核验状态；未核验室内段默认只进入步行搜索空间。
  • 建筑、入口、水域和道路来自 OpenStreetMap，遵循 ODbL 1.0；数据仍未经现场通行性测绘。
  • 3D 渲染图只能提供材质和平面候选，无法单独证明可达性、屋面承载、临边防护或楼层连接。
  • 真实机器人接入前必须增加定位、动态避障、权限与安全停机层。
