# 功能详解

本文按使用视角逐项介绍 LubanNav 的功能、交互与边界。接口层面的字段定义见 [static-api.md](static-api.md) 与 [frontend-modules.md](frontend-modules.md)。

## 1. 三种导航入口（同一路由内核）

所有入口最终都只修改页面的 `from / to / mode` 三个状态，由 `findRoute()` 统一计算路线，保证页面、分享链接与静态 API 使用一致的导航合约。

### 1.1 手动选择

左侧「去哪里？」工作台：

- **导航对象切换**：`步行` / `机器人`。机器人模式使用 `accessibleOnly` 边集（过滤 `wheelchair=no` 与松软路面），速度参数 0.8 m/s；步行 1.25 m/s。
- **A / B 地点下拉框**：列出全部 29 个公开地点；`⇅` 按钮交换起终点。
- **路线摘要**：预计距离、预计耗时、室内路段距离（无室内段时显示路径节点数）。
- **路线详情**：展开后列出中文分步指引（出发 → OSM 道路 → 进楼 / 电梯 → 室内通道 → 室外平台 → 抵达）。
- **复制链接**：把当前地址栏 URL（含 `from/to/mode/event` 查询参数）写入剪贴板。

### 1.2 自然语言文本

对话框支持中英文混合的本地解析（不调用模型）：

| 句式 | 示例 | 解析结果 |
| --- | --- | --- |
| 从 X 到 Y | `从宿舍 5 到饭堂`、`from main gate to library` | 起点 + 目的地 |
| 带我去 / 怎么去 | `带我去图书馆`、`图书馆怎么走` | 沿用当前起点 |
| 机器人 / 轮椅 / 无障碍 | `让机器人从宿舍5去体育馆` | `mode=robot` |
| 问候与常见问答 | `你好`、`今天要带伞吗` | 本地缓存回答（见 §4） |

地点匹配按「归一化精确 → 包含 → Levenshtein 模糊（阈值 0.34）」三级进行，别名表覆盖 `西翼大学`、`W2电梯`、`嘉宾晚宴餐厅` 等口语名称。解析失败时助手会明确追问缺失的是出发地还是目的地，不猜测。

URL 参数 `?q=<文本>` 在页面首次加载时等价于发送一条文本消息；`?from=&to=&mode=` 直接设定路线状态。

### 1.3 实时语音

见 §5。语音同样复用本地解析（转写文本先走本地解析器降低延迟）与 Qwen Function Calling（处理更自然的表达）两层，最终参数都要通过地点白名单验证。

## 2. OSM / WGS84 地图

- **数据**：`public/data/campus-osm.geojson` 同源快照（约 76 KB），只含建筑、入口、道路、水面、水系五类要素；运行期不请求在线瓦片。
- **渲染**：Leaflet Canvas，自定义 pane 层级（水域 220 → 道路 260/270 → 建筑 320 → 室内 380 → 路线 430 → 地点 470）；道路按 `highway` 分级设色与线宽，步道虚线，隧道半透明；室内通道与电梯用独立颜色并带「待核验」tooltip。
- **地点标记**：按分类过滤（全部 / 入口 / 教学 / 室内 / 服务 / 住宿 / 运动）；点击标记直接设为目的地；电梯、平台 POI 有特殊形状颜色；当前目的地高亮并常驻名称标签。
- **路线绘制**：主路线绿色虚线 + 光晕；室内段叠加青色高亮并提示楼层与「近似待核验」；起终点圆点；自动 `fitBounds`。
- **机器人位置**：小车遥测（WiFi RTK 或 BLE 回传）的合法 WGS84 位置以橙色标记显示，tooltip 含航向角；浏览器定位以蓝色半透明圆点兜底，左上角角标显示当前定位源。
- **缩放控制**：`＋ / −` 与「显示完整校园」按钮；地图边界锁定校园范围外扩 20%。

## 3. A\* 分层路网

路网由 OSM 室外道路与本地室内补丁在构建期合并为一张无向图（当前快照：341 节点 / 358 边，OSM 共同连通分量 277 节点，29 个地点全部有绑定）：

1. **道路选择**：`footway / path / pedestrian / service`；过滤 `access=no/private`、`foot=no`；机器人模式额外过滤 `wheelchair=no` 与松软路面（dirt/sand/gravel 等）。
2. **构图**：按 OSM 原始节点 ID 生成米制距离无向边，保留步行与机器人共享的最大连通分量。
3. **入口吸附**（优先级从高到低）：
   - 建筑边界 2.5 m 内的 OSM `entrance=*` 点（`routing:entrance=main` 优先）；
   - 无标签入口时，取建筑边界上距可通行道路节点最近的点，标记 `inferred-building-boundary`；
   - 入口类地点（如主入口）可回退到 150 m 内最近的标签入口；
   - 其余地点直接锚定最近道路节点。
4. **室内网络**：图书馆 0 层走廊、W2/E2 大堂、W2/E2 电梯（服务 1–5F）、三楼室外平台与平台餐厅等；电梯展开为逐层节点与垂直边；大堂入口带 250 m 换楼惩罚（只影响选路，不计入报告距离）。
5. **模式权限**：未核验室内段默认只开放 `pedestrian`；三楼平台及 W2/E2 访问链已确认室外性并开放机器人；平台餐厅与图书馆室内段仍仅步行。

寻路算法为 A\*（Haversine 直线距离启发，边权 = 距离 + 换楼惩罚），起终点使用地点绑定的分模式路由节点，连接段距离计入总距离。无法连通时返回 `status=no_route`。

## 4. AI 对话与本地知识库

左侧对话区的文字助手优先使用确定性本地回答（不调用模型、可离线）：

| 类别 | 触发示例 | 行为 |
| --- | --- | --- |
| 问候 / 感谢 / 告别 | `你好`、`谢谢`、`再见` | 固定友好回复 |
| 自我介绍 / 能力 | `你能做什么` | 说明离线能力与 Open-Meteo 实时天气 |
| 学校简介 / 四大枢纽 / 校址 | `介绍一下学校` | 固定事实回复 |
| 天气 | `今天要带伞吗` | 调 Open-Meteo（免密钥）返回实时温度/降水/紫外线与带伞建议；失败时回退通用提醒 |
| 随身物品 | `出门带什么` | 通用清单提醒 |
| 途经点介绍 | `沿途有什么` | 用当前路线 `highlights` 按到达顺序介绍附近 POI 及用途 |

- **嘘寒问暖**：语音与文字助手都会拿到实时天气（`src/lib/weather.js`，开源免密钥 Open-Meteo，坐标锁定广州南沙区·港科广校园中心，`Asia/Shanghai` 时区，10 分钟缓存）。下雨/高降水概率提醒带伞、注意平台湿滑，晴热或紫外线强提醒防晒补水，雷暴提醒避开空旷平台；目的地是 3 楼露天平台（`third-floor-platform` / `platform-restaurant`）时强制加入平台天气提醒。
- **途经点介绍**：每条路线附带 `highlights`（路线 80 米内、按到达顺序、最多 8 个公开 POI 及用途描述）。长路线（约 800 米以上）语音助手会按顺序一两句话介绍途经点，也可直接问“沿途有什么”。
- **加密航点**：机器人模式下发使用 `navigationWaypoints`——对 `path` 线性插值加密到相邻点 ≤ 2.5 m（`src/lib/routeDensification.js`），满足小车每 2–3 m 一个点的控制需求；原 `path` 仍保留供画线与路段引用。

导航意图优先于闲聊匹配；未命中任何规则时提示换个说法。实时语音启用后，Qwen 负责对话理解，但导航动作仍由本地内核执行（见 §5.3）。

## 5. 实时语音助手（Qwen Realtime）

### 5.1 建连流程

```text
点击「开始语音」
  → getUserMedia 获取麦克风（track 默认静音）
  → RTCPeerConnection + DataChannel("oai-events")
  → 生成 Offer SDP，等待 ICE gathering 完成（8 s 超时）
  → POST 网关 /voice/session（访问码 + Offer SDP）
  → 收到 Answer SDP，setRemoteDescription，WebRTC 连通
  → session.update 下发 instructions / 音频格式 / VAD / 工具定义
  → session.updated 后打开麦克风，进入聆听
```

- 模型：`qwen3.5-omni-flash-realtime`，音色 `Tina`；输入 PCM 16 kHz、输出 PCM 24 kHz；ASR 转写模型 `qwen3-asr-flash-realtime`；`semantic_vad`（全双工 threshold 0.5 / 静音 800 ms；按住说话 0.7 / 2500 ms）。
- **单次会话前端限制 10 分钟，到期自动续接**；网络波动自动重连（1→15 s 退避，授权/并发类错误切 60 s 慢速档），行走演示不会因校园网抖动静默断线。支持两种交互模式：全双工（默认）与按住说话（嘈杂环境更稳定，按住开麦、松开结束本轮）。访问码保存在本浏览器 localStorage（键 `luban-nav:voice-access-code`，清空输入框即删除），也可用 `?accessCode=` 链接参数预填并覆盖保存；交互模式保存在 `luban-nav:interaction-mode`。
- 音频由浏览器与百炼直连；只有 SDP 交换经过函数计算（见 [voice-gateway.md](voice-gateway.md)）。

### 5.2 界面

- 设置入口：右上角三明治菜单「实时语音」页（输入演示访问码）。
- 快捷控制：地图正下方常驻大麦克风——已配置时一键开始 / 结束会话，未配置时点击直接打开语音设置；会话中显示实时转写与状态文案。

### 5.3 导航工具调用（Function Calling）

模型可调用唯一工具 `set_navigation_route`：

```json
{ "from": "main-entrance", "to": "w4", "mode": "pedestrian" }
```

- `from` 可省略（沿用当前起点）；`to` 必填；两者都必须是地点 ID 枚举值；`mode ∈ {pedestrian, robot}`（机器人 / 轮椅 / 无障碍表达映射为 robot）。
- 页面收到工具调用后：白名单解析 → `findRoute()` 验证可连通 → 更新地图与地址栏 → 把真实距离 / 耗时作为工具结果回传模型，由模型语音确认。
- 地点不明确或不在白名单时返回错误，助手应追问而不是猜测；模型永不生成路径坐标。

### 5.4 状态机

`idle → requesting-microphone → connecting → authorizing → listening ⇄ user-speaking / thinking / assistant-speaking → ended / error / time-limit`。浏览器不支持 WebRTC、麦克风被拒、网关 4xx/5xx、模型错误都有对应的中文提示。

### 5.5 语音模板（主动提醒 + 实时上下文）

`buildCampusAssistantInstructions`（`src/lib/assistantKnowledge.js`）内置主动提醒与自动刷新的实时上下文，随 instructions 下发给模型：

- **会话开场（先问去向 + 出发提醒）**：每次会话第一句先询问用户想去哪里（如“您好，请问您想去哪里？”），目的地不明确时追问而不猜测；用户给出目的地、路线确定后，若本会话尚未提醒过，再按实时天气给出出发提醒——正在降雨或今日降水概率较高时明确提醒“出门带伞、注意湿滑”；晴热或紫外线强时提醒防晒补水；天气平稳时也自然带一句“出门记得带伞”。数据来自开源 Open-Meteo（广州南沙区·校园中心）。
- **出发放包提醒（机器人模式）**：路线模式为机器人/小车时，出发前若用户携带背包等随身物品，提醒可先将包放到随行小车自带的载物平台上，由小车携带出发；不要编造载物平台未确认的信息（如容量、承重、固定方式）。步行模式不注入此提醒。
- **到达提醒**：当用户表示接近或已到达目的地（如“快到了”“还有多远”“到门口了”“到了”），像公交到站提示一样简短提醒“请带好随身物品”（背包、手机、校园卡、钥匙等）；没有到达迹象时不反复提醒。
- **实时上下文自动刷新**：`buildLiveContext` 每 30 秒重建一次并推送 `session.update`——包含当前日期时间（`Asia/Shanghai`）与导航进度。进度优先用机器人 BLE 遥测位置沿路线计算（`distanceAlongPolylineMeters`，真实进度）；无遥测时按“路线开始时间 + 全程耗时”做匀速估算（明确标注估算、不得当作精确位置）。进度显示接近目的地时，指令提示模型可主动提醒“带好随身物品”（若尚未提醒）。
- 目的地是 3 楼露天平台时额外加入**平台提醒**（带伞 / 防滑 / 防晒 / 雷雨避让）。

## 6. 会议与活动专属导航

「活动专属导航」面板为会议 / 活动提供场所级导航：

- **场所角色**：主会场、签到地点、分会场（多个）、住宿地点（多个）、推荐食堂（多个）。每个场所含显示名称、地图地点 ID、楼层、房间、现场说明；只有绑定了公开地图地点的场所才能触发导航。
- **配置方式**：下拉选择活动 → 「配置」编辑；`＋` 新建；保存写入浏览器 `localStorage`（key `lubannav.event-profiles.v1`），不跨设备同步。全员共享的活动应写入 `src/data/events.js` 并重新部署（随后可由 `GET api/v1/events.json` 读取）。
- **内置默认活动**：`八月真机展示活动`（主会场三楼，其余待配置）；组织者可随时「恢复默认」。
- **导航触发**：点击场所「导航」按钮，或说「带我去主会场」「去签到点」；角色关键词匹配与场所名匹配均支持，多匹配或场所未绑定时明确提示，不猜测。
- **分享链接**：`?event=<id>` 指定活动，`event=none` 表示普通校园导航。
- **语音上下文**：活动配置会注入助手 instructions，模型可回答场所安排，但同样不能为未绑定地点编造 ID。

## 7. 机器人控制（WiFi 直连 + Web Bluetooth 双链路）

机器人面板提供两种传输方式，协议完全一致（JSON Lines，见
[robot-ble-protocol.md](robot-ble-protocol.md)）：

- **WiFi 局域网（推荐，默认）**：WebSocket 直连车机 `ws://10.7.181.161:8900/`
  （`car7-wifi-bridge`，部署见 [robot-wifi-link.md](robot-wifi-link.md)）。
  车机 Intel 组合卡 WiFi/BT 共存压制 BLE 广播（实测 WiFi 占用时 0 条广告/60 s），
  导航链路优先走 WiFi。**HTTPS 页面不能访问 `ws://` 局域网地址**（混合内容），
  联调请用 `http://localhost:5173` 本地开发页或 HTTP 部署页；正式 HTTPS 需 `wss://`。
- **蓝牙 BLE**：Web Bluetooth GATT 直连（`car7-ble-bridge`）。需要 HTTPS 安全
  上下文与支持 Web Bluetooth 的 Chromium 浏览器；设备选择必须由按钮点击触发。

- **入口**：右上角菜单「机器人联络」页。连接/设置按所选传输显示。
- **GATT 与分包设置**：设备名前缀（默认 `car7`，可空）、Service / Command(RX) / Telemetry(TX) 三个 UUID（默认 Nordic UART Service）、每包字节（默认 185，1–512）、包间隔（默认 5 ms，0–1000）。设置持久化在 `localStorage`。默认按现代 BLE MTU（Android+BlueZ ≥185B）调优：89 KB 加密路线从约 53 s 降到约 4 s；旧 20B MTU 固件请手动调回。
- **连接诊断**：按 `device-selection → gatt-connect → primary-service → command-characteristic → telemetry-characteristic → notifications` 六阶段报错，每阶段给出针对性中文建议（例如 `primary-service` 失败说明固件不是 NUS，需要用 nRF Connect 读真实 GATT 表）。
- **下发路线**：仅 `robot` 模式路线可发送；必须人工点击「下发当前路线」，路线变化不会自动推送。消息为 UTF-8 JSON Lines，按字节分包顺序写入；传输进度条实时显示分片进度。
- **STOP**：中止未完成的路线传输（先写一个 LF 让固件丢弃半行），优先发送 `emergency_stop`。它只是辅助入口，不能替代物理急停。
- **遥测**：回传 `position / ack / status`。WiFi 链路的位置来自真机 RTK
  （`/fix` + `/imu` + `/odom`，2 Hz，`fixStatus` 标注固定解/浮点解/回放；
  室内无固定解时按路线航点回放以便演示闭环）。合法 WGS84 位置显示在地图与
  面板上；通信记录保留最近 5 条。
- **定位融合与实时进度**：小车 RTK 位置 5 秒内新鲜 → 用 RTK；否则回落浏览器
  定位（`watchPosition` 高精度，兜底）。地图橙色圆点 = 小车 RTK（含航向），
  蓝色半透明圆点 = 浏览器定位，左上角角标显示当前定位源。面板实时显示定位源、
  速度、沿路线的剩余距离/进度百分比与距下一航点距离。
- **断连安全**：连接断开时自动取消传输、释放引用、重置解码缓冲；WiFi 链路
  意外断线按指数退避自动重连（1→15 s）。

## 8. 可通行面候选（研究性数据）

从本地 3D 俯瞰渲染图提取水泥色平面候选，并配准到 WGS84，作为未来扩展路网的备选面。**全部要素 `routingEnabled=false`，不进入 A\* 路网。**

1. `npm run extract:walkable`：颜色阈值（低饱和 / 低色差 / 足够亮度）+ 形态学开闭运算提取候选掩膜，网格化连通分量 + 边界环追踪 + 折线简化输出归一化图像坐标 GeoJSON、掩膜 PNG、叠加预览与摘要（含源图 SHA-256）。
2. `npm run register:walkable`：以 OSM 中 E1–E4、W1–W4 八栋楼质心为控制目标，对图像像素控制点拟合投影单应矩阵，把候选面变换到 WGS84；报告记录每栋楼的拟合残差（米）、反投影残差（像素）与留一验证残差，并按配置阈值（拟合最大残差 ≤ 15 m、留一最大残差 ≤ 45 m）判定 accepted / rejected。
3. 配准通过只表示几何对齐可用，不表示通行资格；进入导航前仍须完成地面 / 屋顶 / 立面分类、高程与垂直连接核验。

## 9. GIS 导出（供 QGIS 人工编辑）

`npm run export:gis` 把应用数据导出为五个 EPSG:4326 图层：室内路径、室外路径、POI 点、建筑面、可通行面候选，输出 `artifacts/gis/` 下的分层 GeoJSON、多图层 GeoPackage（需要 `ogr2ogr`）与带样式 / 捕捉设置的最小 QGIS 工程文件。详见 [data-pipeline.md](data-pipeline.md)。

## 10. PWA 与离线属性

`public/manifest.webmanifest` 提供应用元信息；页面本身依赖的全部数据（地图、路网、路线、知识库）都是同源静态资源，加载完成后可离线使用。实时语音与 BLE 功能依赖网络 / 硬件，属于可选增强。

## 11. 安全与合规边界

- OSM 数据署名 © OpenStreetMap contributors，许可证 ODbL 1.0；地图右下角与页脚均有署名与来源链接。
- 导航拓扑未经现场测绘；室内段均为近似数据并带核验状态标记。
- 真实机器人部署至少还需：厘米级定位、现场可通行性校验、动态避障、门禁 / 电梯接口、实时封路、速度与制动安全层、失联看门狗与实体急停。
